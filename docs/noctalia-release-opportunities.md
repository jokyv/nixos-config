# Noctalia v5.1.0 and v5.0 release opportunities

## Enabled on `jokyv`

- `Mod+Shift+Y` opens Noctalia's region capture with annotation enabled; saved images use `~/pics/screenshots`. `Mod+Y` still runs the original screenshot helper.
- Explicitly dismissed notifications leave history (`notification.keep_dismissed_in_history = false`); expired notifications remain for at most 30 days (`notification.history_retention_hours = 720`).
- `Alt+Tab` opens Noctalia's MRU window switcher (`shell.window_switcher.mru = true`).
- Launcher includes searchable `.desktop` actions (`shell.launcher.show_app_actions = true`), including Firefox's New Private Window.

The opportunity descriptions below record the earlier research snapshot; these four settings are now configured in `home/programs/noctalia/` and `home/programs/niri.nix`. Noctalia GUI overrides in `~/.local/state/noctalia/settings.toml` take precedence over Home Manager's config.

## Release and repository version context

There is no official final `v5.0.0` release/tag: the official tag URL returns 404, and the official release feed lists `v5.0.1` followed by `v5.0.0-beta.10`. The `v5.0.1` notes explicitly call it the stable graduation of v5, so stable v5.0 opportunities below are attributed to `v5.0.1`, not to a final `v5.0.0`. The beta.10 notes are useful prerelease context only; they mention per-event calendar colors and past-event fading, among other changes. ## v5.1.0 opportunities

- **DDC/CI monitor rescan:** v5.1.0 adds manual rescanning for DDC/DisplayPort monitors when using `ddcutil`. This repository already installs `ddcutil` on `jokyv`, but Noctalia has `brightness.enable_ddcutil = false`. Consider enabling it only if attached monitors support DDC/CI; `ddcutil` is an optional dependency, and enabling the setting alone does not make unsupported displays controllable. [Release notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.1.0) · [brightness settings and DDC/CI prerequisites](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/services/brightness.mdx) · [optional dependency](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/BUILDING.md) · local: [`ui.nix`](../home/programs/noctalia/ui.nix), [`jokyv` packages](../hosts/jokyv/packages.nix)
- **Notification history policy:** v5.1.0 adds `notification.keep_dismissed_in_history`. The v5.1 example config defaults it to `true`; setting it to `false` removes dismissed toasts from history. The repository configures other notification behavior but omits this field, so making a deliberate choice here would document the desired policy. No extra service or package is needed. [Release notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.1.0) · [v5.1 default config](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/example.toml) · [notification behavior](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/services/notifications.mdx) · local: [`notifications.nix`](../home/programs/noctalia/notifications.nix)
- **Enterprise Wi-Fi and cellular:** v5.1.0 adds WPA2/WPA3 Enterprise (802.1X) Wi-Fi credentials in Control Center and cellular controls backed by ModemManager. The `jokyv` host already enables NetworkManager, which is included in Noctalia's documented recommended services. Enterprise Wi-Fi is relevant only for an 802.1X network. Cellular support needs compatible modem hardware and ModemManager enabled separately; Noctalia's recommended-services list does not include ModemManager. [Release notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.1.0) · [Noctalia NixOS services](https://docs.noctalia.dev/noctalia/getting-started/nixos/) · [NixOS ModemManager option](https://search.nixos.org/options?channel=unstable&show=services.modemmanager.enable) · local: [`networking.nix`](../hosts/jokyv/networking.nix)
- **Screenshot annotations:** v5.1.0 adds an in-shell region editor with drawing and blur tools. To use it declaratively, add the built-in `screenshot` widget to a bar lane and set `shell.screenshot.annotate = true`; `close_on_copy` controls whether a successful copy closes the editor. The widget requires compositor `wlr-screencopy`; its guide lists Niri as supported, matching this repository's compositor. Niri's own screenshot path is configured separately, so set `shell.screenshot.directory` if Noctalia captures should also go to `pics/screenshots`. [Release notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.1.0) · [screenshot widget requirements](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/bar/widgets/screenshot.mdx) · [screenshot settings](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/configuration/shell.mdx) · local: [`bar.nix`](../home/programs/noctalia/bar.nix), [`niri.nix`](../home/programs/niri.nix)

## v5.0.1 opportunities

- **Most-recently-used window switching:** v5.0.1 adds optional MRU ordering for the window switcher. Set `shell.window_switcher.mru = true` if Alt+Tab should order windows by recency instead of workspace layout. The v5.1 default config sets it to `false`, and the tagged config schema includes the field; the v5.1 shell prose says the switcher has no settings, so upstream docs conflict on this point. The release notes, shipped default, and schema agree that MRU is configurable. No extra dependency. [v5.0.1 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.1) · [versioned setting/default](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/example.toml) · [versioned config schema](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/src/config/schema/config_schema.cpp)
- **Bluetooth widget visibility:** v5.0.1 adds `widget.bluetooth.hide_when_adapter_off`. The bar already includes the Bluetooth widget, while Bluetooth is enabled at boot; set this only if hiding an intentionally powered-off adapter is preferred. While hidden, the widget's right-click power toggle is unavailable, but the existing Control Center Bluetooth shortcut remains available. [v5.0.1 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.1) · [Bluetooth widget setting and caveat](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/bar/widgets/bluetooth.mdx) · local: [`bar.nix`](../home/programs/noctalia/bar.nix), [`ui.nix`](../home/programs/noctalia/ui.nix), [`hardware.nix`](../hosts/jokyv/hardware.nix)
- **Local vdir calendars:** v5.0.1 adds local vdir/vdirsyncer calendar accounts with live directory monitoring. Calendar is already enabled here, but no account is declared in the Noctalia settings. Add a `calendar.account.<id>` with `type = "vdir"` and a `path` only if there is a local vdir calendar directory; vdirsyncer is an optional external way to populate/synchronize that directory. For CalDAV or Google accounts instead, observe the separate credential and Secret Service requirements in upstream docs. [v5.0.1 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.1) · [v5.1 calendar setup and credentials](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/services/calendar.mdx) · local: [`ui.nix`](../home/programs/noctalia/ui.nix)
- **Independent shell and app theme modes:** v5.0.1 adds a separate dark/light mode for applications. The current config forces `theme.mode` to dark and does not set `theme.shell_mode`. If the intended policy is different shell and app modes, set `theme.shell_mode` independently; v5.1 docs define `theme.mode` as the app mode and `shell_mode` as Noctalia's own mode. No external dependency is involved. [v5.0.1 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.1) · [theme setting semantics](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/theming/index.mdx) · local: [`ui.nix`](../home/programs/noctalia/ui.nix)
- **Wallpaper favorites:** v5.0.1 adds favoriting the current wallpaper from the wallpaper panel. The existing config already defines a wallpaper directory and rotation; starred favorites can make preferred images easier to find, or can be declared as `[[wallpaper.favorite]]` entries with theme presets. No additional package is documented as a prerequisite. [v5.0.1 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.1) · [favorites configuration and behavior](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/desktop/wallpaper.mdx) · local: [`wallpaper.nix`](../home/programs/noctalia/wallpaper.nix)

## v5.0.0-beta.9 opportunities retained in v5.1.0

These are beta features, not additions attributed to a final v5.0.0 or to v5.0.1. They remain configurable in the v5.1.0 docs/schema and are present in the repository's newer pin.

- **Workspaces from all outputs:** beta.9 added optional `widget.workspaces.show_all_outputs`; it is still documented in v5.1.0. The bar already has a workspace widget. Enable only for a multi-monitor setup where showing every monitor's workspaces is useful; the bar's own monitor stays first. [beta.9 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.0-beta.9) · [v5.1.0 workspace setting](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/bar/widgets/workspaces.mdx) · local: [`bar.nix`](../home/programs/noctalia/bar.nix)
- **Searchable desktop actions:** beta.9 added optional desktop-file actions in launcher results. Set `shell.launcher.show_app_actions = true` if installed apps expose useful `.desktop` actions; without such actions, no new results appear. [beta.9 notes](https://github.com/noctalia-dev/noctalia/releases/tag/v5.0.0-beta.9) · [v5.1.0 launcher setting](https://github.com/noctalia-dev/noctalia/blob/v5.1.0/docs/user/configuration/shell.mdx) · local: [`launcher.nix`](../home/programs/noctalia/launcher.nix)
